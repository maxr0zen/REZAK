# Rezak Studio

Локальная студия автоматических нарезок: отдельное окно приложения, загрузка видео, Twitch-мониторинг и фоновая очередь. Whisper и Bonsai2 работают последовательно в отдельных Docker-контейнерах, запись Twitch не занимает GPU.

Интерфейс: React + Vite (`frontend/src`). Backend: FastAPI (`rezak/web.py`). FastAPI раздаёт готовую сборку из `rezak/static/react`; Node.js при обычном запуске не требуется. После изменений интерфейса выполните `npm.cmd --prefix frontend ci` и `npm.cmd --prefix frontend run build`. Подробности разработки — [frontend/README.md](frontend/README.md).

Для новых TikTok доступен нижний видеоряд из локальной библиотеки: поднятый основной стрим, субтитры между панелями, паркур без звука снизу. Настройка и авторство — [BACKGROUND_VIDEO.md](BACKGROUND_VIDEO.md).

Аккаунты YouTube/TikTok привязываются к отдельным стримерам. Отправка готового ролика после подтверждения идёт в отдельной очереди: YouTube upload и TikTok Inbox с завершением публикации в приложении. Подключение OAuth и ограничения — [PUBLISHING.md](PUBLISHING.md).

## Запуск

### Установка после клонирования

Для Windows нужны Git, Python 3.11–3.14, uv и Docker Desktop с поддержкой NVIDIA GPU.

```powershell
git clone https://github.com/maxr0zen/REZAK.git
cd REZAK
uv sync --locked
Copy-Item .env.example .env
```

Укажите в `.env` путь к модели и выполните настройку по [DOCKER_AI.md](DOCKER_AI.md), затем соберите контейнеры: `docker compose --profile recorder build app recorder asr`. Запустите `Запустить Rezak.cmd`. Собранный React-интерфейс уже включён в репозиторий; Node.js нужен только для его разработки.

Записи, экспорты, модели, локальная база с аккаунтами, OAuth-токены и `.env` в Git не входят. На новом компьютере подключите аккаунты заново. Дополнительный нижний видеоряд устанавливается отдельно по [BACKGROUND_VIDEO.md](BACKGROUND_VIDEO.md).

Откройте **Запустить Rezak.cmd** в папке проекта. Скрипт запускает локальную службу и отдельное окно Chrome/Edge. Также доступен адрес http://127.0.0.1:8765. Это локальное веб-приложение в отдельном окне, пока без установщика EXE.

На этом компьютере зависимости и Docker-образы установлены. Docker Desktop должен работать. При переносе: `uv sync --locked`, настройка моделей по [DOCKER_AI.md](DOCKER_AI.md), `docker compose --profile recorder build app recorder asr`.

- **Обзор:** перетащите видео или нажмите «Добавить видео», выберите 9:16, 16:9 или оба формата. Импорт сохраняет оригинал отдельно, допустимы MP4/MKV/MOV/WEBM/TS/M4V до 20 ГБ.
- **Очередь:** реальные этапы подготовки, распознавания, отбора, монтажа и проверки; проценты этапов, длительность, таймкоды, сообщения процессов, фильтр ошибок и скачивание журнала. Загрузка модели не имеет выдуманного процента. Отмена сохраняет исходники; ошибочную задачу можно повторить.
- **Twitch-стримеры:** добавление по логину/ссылке, отдельные переключатели отслеживания, автозаписи и нарезки, выбор качества.
- **Нарезки:** превью, просмотр, скачивание и открытие папки результатов. Синтетические тестовые записи помечены.

## Подключение Twitch

В «Настройки» введите **Client ID** и **Client Secret** приложения из https://dev.twitch.tv/console/apps. Кнопка проверяет ключи до сохранения. Secret хранится через Windows DPAPI для текущей учётной записи, интерфейс его не возвращает. Используется app access token; пароль Twitch не нужен.

Монитор опрашивает Helix каждые 30–300 секунд, до 100 каналов. Один эфир автоматически запускается один раз. Streamlink сохраняет независимые части TS по 15 минут; закрытая часть поступает в очередь, пока следующая продолжает записываться. Включённый компьютер, интернет и работающая служба необходимы. После закрытия окна служба продолжает работу; выход — «Настройки → Завершить работу» либо `scripts/stop-studio.ps1`. Автозапуск Windows и пробуждение из сна не настроены.

Границы частей и переподключения могут иметь пропуски: это не бесшовный архив. Manifest сохраняет исходный PTS, time base и время запроса/завершения записи; они не гарантируют точную привязку к часам Twitch. Лимит одной сессии — 24 часа. При свободном месте менее 1 ГБ запись останавливается. После сбоя сохранённые части можно отправить на обработку кнопкой восстановления. Реальный эфир без пользовательских ключей пока не проверен.

## Данные и ограничения

Очередь, настройки и история — `data/app/studio.sqlite3`, журналы — `data/app/logs`, оригиналы — `data/imports`, эфиры — `data/recordings`, результат — `data/exports`. После перезапуска прерванная задача отмечается явно, автоматическое продолжение незаконченного процесса не обещается. Не удаляйте эти каталоги и Docker volumes моделей.

Текущий монтаж — технический baseline: вертикаль 360×640, горизонталь 640×360, H.264/AAC, субтитры. Кадр целиком вписывается с полями; слежение за лицом/webcam-композиция и production-пресеты ещё не реализованы. Готовые моменты и текст нужно проверить перед публикацией. На RTX 5060 Ti 8 ГБ модели загружаются по очереди; старт Bonsai2 может занимать несколько минут при нехватке RAM.

## Движок и техническая проверка

## Проверенный запуск Windows

В текущем рабочем каталоге зависимости уже установлены в `.venv`. Для повторной установки: `uv sync --locked`. Нужны FFmpeg с libx264/libass и ffprobe; пути задаются переменными `FFMPEG` и `FFPROBE` (иначе поиск в PATH).

```powershell
$env:FFMPEG = (.venv\Scripts\python.exe -c "import imageio_ffmpeg; print(imageio_ffmpeg.get_ffmpeg_exe())")
$env:FFPROBE = "$PWD\.tools\ffprobe.exe"
.venv\Scripts\python.exe -m scripts.smoke
$env:REZAK_INTEGRATION = '1'
.venv\Scripts\python.exe -m pytest -q
```

Smoke создаёт шестисекундный синтетический источник, режет два интервала по две секунды, добавляет кириллические субтитры, проверяет метаданные и полное декодирование, сохраняет контрольный кадр. Результаты: `data/exports/`. `.tools/ffprobe.exe` загружен для этой проверки из eugeneware/ffprobe-static (3.0.1); для дальнейшей эксплуатации нужен современный FFmpeg/ffprobe из одной сборки. Бинарники не входят в исходники.

## Своя запись

Поместите копию файла в `data/sources/имя.mp4`. В плане укажите `source_id: "имя"` (латинские буквы, цифры, `_` и `-`). Оригинал движок не меняет. Пример плана — `examples/manual.json`.

```powershell
.venv\Scripts\python.exe -m rezak render examples/manual.json --data data
```

Времена — целые миллисекунды, интервалы `[start,end)`, относительно первого видеокадра. Субтитры используют исходные времена и пересчитываются в порядок монтажа. Допускается перестановка непересекающихся интервалов; дубли и перекрытия запрещены. Потери записи можно задать в `data/sources/имя.gaps.json`: список объектов `start_ms/end_ms`.

Профили baseline: vertical 360×640, horizontal 640×360, 30 fps, H.264/AAC stereo. Это техническое превью, не финальный production-пресет. `fit_pad` сохраняет весь кадр; webcam/two-zone и произвольное кадрирование ещё не реализованы. Вертикальный план ограничен 180 секундами, горизонтальный — часом. Требуется видео с аудиодорожкой. HDR, поворот, сложные разрывы PTS и длинные записи не проверены. Сложные ASS-теги в субтитрах запрещены; автоматический подбор размера длинного текста ещё не реализован.

Выход получает уникальное имя. Сначала рендерится временный MP4, затем проверяются размер/длительность/дорожки и полное декодирование. Только после проверки файл публикуется атомарным rename. Рядом сохраняются план и ffprobe JSON. Отмена через Ctrl+C завершает запущенный процесс; программный API принимает threading.Event. Журналы процесса ограничены по памяти. Очередь и восстановление сохранённых частей реализованы в Studio.

## Ручной CLI в Docker

```powershell
docker compose config --quiet
docker compose build
docker compose run --rm -v "${PWD}/data/sources:/data/sources:ro" app render examples/manual.json
```

Основные образы собраны и проверены. Актуальные GPU-контейнеры и volumes описаны в DOCKER_AI.md; приложение Studio управляет ими с хоста.

Python-зависимости зафиксированы в uv.lock и requirements.lock с хешами. Образ Python закреплён тегом; OS-пакеты Debian не зафиксированы snapshot-репозиторием, поэтому побитовая воспроизводимость образа пока не гарантируется.


## Редактирование готовых нарезок

В галерее у каждого ролика есть «Редактировать» и удаление с подтверждением. Название меняется только у выбранного экспорта. В редакторе можно дать задание Bonsai2 для этой нарезки (например, сохранить объяснение и закончить фразу): используются сохранённая расшифровка и до 15 секунд контекста вокруг выбранных исходных интервалов. Задание управляет выбором эпизодов и границами монтажа по речи; новые кадры, музыка и реплики не генерируются. Результат сохраняется копией через очередь, с журналом. Если законченный эпизод под задание не найден, задача сообщает ошибку и сохраняет прежний ролик.

Точная обрезка доступна в раскрывающемся блоке: секунды с точностью до миллисекунд, границы по курсору, просмотр интервала. Это буквальные ручные границы; проверяйте их на слух. Обрезка пересобирает копию по исходному плану, поэтому субтитры пересчитываются без повторного распознавания. Исходный файл записи нужен для повторного монтажа. Доработка по промпту требует сохранённой расшифровки в Docker volume.

Удаление переносит ролик и одинаковые повторные экспорты в `data/trash/<token>/`; оригинал стрима остаётся. Кнопка «Восстановить» в уведомлении возвращает последнее удаление. Автоматическая очистка корзины не включена; её файлы продолжают занимать место. Ранее удалённые группы доступны через API `/api/trash/{token}/restore` по имени папки; отдельного экрана корзины пока нет.

Автоматический выбор границ учитывает таймкоды слов, завершение фразы/паузу и безопасный хвост. Возле конца исходника сохраняется оставшийся хвост до 1,5 секунды. При отсутствии безопасного окончания в пределах 8 секунд кандидат отклоняется. Уже экспортированные файлы не меняются автоматически: для пересборки используйте редактор с заданием сохранить окончание. Если слово обрезано в самом исходнике, его нельзя восстановить этим методом. ASR-ошибки и смысловое завершение требуют проверки человеком.


## Скачать опубликованную запись Twitch

Для доступного VOD используйте установленный контейнер recorder:

```powershell
.venv\Scripts\python.exe scripts/download-vod.py https://www.twitch.tv/videos/2892792614 --quality best
```

Скрипт сохраняет запись в `data/recordings/vod_ID/recording.ts`, метаданные и `download.log`. `best` выбирает максимальное доступное качество; можно явно указать, например, `720p60`. Сначала создаётся `recording.part.ts`; окончательное имя присваивается после успешного завершения Streamlink и проверки наличия видео/аудио через ffprobe. При сбое частичный файл остаётся для диагностики. Существующие файлы не перезаписываются; автоматического продолжения неполного скачивания пока нет. Файл TS можно добавить в студию как обычную запись. Скачивание не запускает нейросети.

## Монтаж по форматам и экспорт 1080p

### Актуальная сборка: один итоговый ролик и TikTok 720p

Горизонтальный экспорт остаётся 1920×1080. Вертикальный TikTok теперь 720×1280; пословная подсветка масштабируется вместе с кадром. Отдельный поиск коротких моментов допускает обычные удачные шутки, мнения и реакции, а не только исключительные хайлайты. Обычный интервал 4–30 секунд (предпочтительно 10–25); до 120 секунд разрешается только явно отмеченному сильному эпизоду с высокими оценками интереса/темпа. Количество не добирается квотой. Проверенные тихие паузы по-прежнему сокращаются.

Полноценные фрагменты больше не превращаются в десятки отдельных загрузок. После локального анализа выполняется общий отбор по интересу, связности и новизне, с включением необходимых соседних эпизодов. Выбранное соединяется хронологически в один ролик. Для исходника до трёх часов ориентир 30 минут, затем 45–60 минут для длинных эфиров; исключительное обилие сильного материала на длинном стриме может увеличить цель до 75 минут. Это бюджет, а не обещание добрать слабые эпизоды до минимума. Для текущей записи явно задан ориентир 30 минут.

Уже отрендеренные совместимые фрагменты отбираются и соединяются через concat без повторного кодирования, с полной проверкой декодирования. После успеха промежуточные горизонтальные файлы остаются на диске, но скрываются из галереи через `superseded_by`. Если итоговый файл убран, они снова доступны. Расшифровка для повторного отбора TikTok и длинной сборки используется из кеша; Whisper повторно не запускается.

Новые экспорты: 1920×1080 (полные ролики) и 720×1280 (TikTok), H.264 CRF 20, 30 fps, AAC stereo. Кадр целиком сохраняется с полями по прежнему шаблону fit_pad; автоматическое кадрирование лица пока не применяется. Исходник низкого разрешения масштабируется, дополнительных деталей это не создаёт. Старые MP4 не изменяются.

Полные ролики отбираются отдельно от TikTok. Сохраняются развитие активности, объяснения, попытки, реакции и завершения; каждый фрагмент не обязан быть самостоятельным хайлайтом. Модель получает краткую память предыдущего окна и отмечает продолжение мысли и крупную смену активности. Связанные интервалы объединяются с промежуточной речью, пересечения удаляются без потери продолжения. Темы и активности образуют библиотеку кандидатов, из которой общий отбор собирает один итоговый ролик около 30–60 минут.

Для TikTok достаточно понятного удачного момента: оценка начала от 3/5, темпа от 2/5, подводка до 6 секунд. Обычный интервал 4–30 секунд, предпочтительно 10–25; до 120 секунд только при exceptional=true, начале от 4/5 и темпе от 3/5. Оценка основана на расшифровке и таймкодах; количество не добирается квотой.

Новая версия анализа имеет собственный кеш. Старая расшифровка используется повторно, старый отбор хайлайтов не подмешивается. В `candidates.json` сохраняются решения, связи между окнами, длительности активностей и причины отклонения коротких кандидатов. Итоговая длина зависит от содержания; фиксированная доля исходника не гарантируется. Результаты модели требуют просмотра человеком.

### Названия готовых видео

После рендера отдельный запрос Bonsai2 составляет короткое название по речи, которая действительно вошла в этот ролик: конкретный момент для TikTok и основная тема для полного видео. Служебные причины отбора, оценки «хука», имена файлов и неподтверждённые события не должны становиться названием. Для длинного ролика используются выдержки из начала, середины и конца. Сохраняются ссылки на ASR-сегменты, на которых основан заголовок. У частей длинной активности сохраняется номер части.

Названия имеют отдельный кеш и не меняют кеш отбора эпизодов. При недоступности модели берётся короткая дословная выдержка из выбранной речи. Ручное переименование сохраняется; скачиваемое имя строится по отображаемому названию с безопасными для Windows символами. Внутренние имена MP4 остаются стабильными для ссылок, очереди и корзины.

### Политика субтитров

Полноценные ролики не содержат постоянной расшифровки на экране. Допустим только отмеченный моделью исключительный момент с конкретным обоснованием и оценкой 5/5: точная короткая цитата, до 6 секунд, не чаще одного акцента за 20 минут и суммарно до 1% длительности ролика. Фильтр действует и при рендере старых планов; обычные речевые субтитры в горизонтальном формате не прожигаются.

В TikTok используются ASS-субтитры: группы до трёх слов, подсветка текущего слова по таймкодам Whisper и короткое увеличение при появлении. Если пословных таймкодов нет, показывается фраза без искусственной синхронизации отдельных слов. Автомонтаж сокращает длинные паузы только при совпадении разрыва между словами и подтверждённого FFmpeg тихого участка (порог −38 dB); вокруг слов остаются защитные поля. Паузы под громкую музыку и реакции без подтверждённой тишины не вырезаются этим правилом. Ложные или неточные таймкоды всё ещё требуют ручного просмотра.

### Память распознавания

ASR декодирует аудио потоком и распознаёт части по 60 секунд с контекстом по 2 секунды на границах. Весь эфир не загружается в память. Лимит контейнера остаётся 3 ГБ. Таймкоды слов пересчитываются относительно исходной записи; слова на перекрытиях распределяются по середине слова без принудительного обрезания.

Каждая законченная часть атомарно сохраняется в Docker volume `rezak_artifacts`, каталог `/data/transcripts/checkpoints/`. Повтор задачи использует эти части, если исходник и настройки ASR совпадают. Полная расшифровка публикуется только после последней части. Не удаляйте volume, если нужны восстановление и редактирование по расшифровке. Прогресс отражает обработанное время исходника, журнал показывает сохранённые части.

Код Docker 137 означает принудительное завершение процесса; причину нужно проверять в событиях ядра. Для записи Twitch 2892792614 подтверждено превышение лимита памяти прежним ASR, который декодировал всё аудио сразу. Предупреждение ONNX о telemetry device ID не было причиной остановки.

У Bonsai2 также подтверждён OOM при анализе длинной записи. Встроенный кеш состояний llama-server по умолчанию допускал 8192 МиБ при лимите контейнера 5 ГБ. Теперь `--cache-ram 256` ограничивает его, а `--ctx-checkpoints 0` отключает дополнительные снимки контекста в RAM. Это внутренний кеш модели, а не сохранённые результаты анализа. Docker может перезапустить упавший сервер до трёх раз. При обрыве соединения клиент ждёт готовности API до 360 секунд и один раз повторяет тот же запрос. Ошибки JSON имеют отдельный лимит двух попыток. Завершённые окна анализа сохраняются атомарно и используются при повторе задачи; исходник и расшифровка не меняются.
