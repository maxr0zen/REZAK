# Аккаунты и отправка роликов

Rezak поддерживает несколько своих YouTube-каналов и TikTok-аккаунтов. Один аккаунт закрепляется за одним стримером; у стримера может быть по одному аккаунту каждой площадки. Эти привязки не создают новые аккаунты на площадках: сначала нужно иметь свои аккаунты и разрешить Rezak доступ к каждому из них.

## Подключение

1. Запустите студию обычным способом и откройте **Twitch → Аккаунты площадок**.
2. Один раз настройте OAuth-приложение для каждой нужной площадки. Client ID / Client key и Client Secret — данные приложения разработчика, не пароль аккаунта. Секрет после сохранения не возвращается в интерфейс.
3. Нажмите **Подключить ещё один аккаунт**, затем перейдите на сайт площадки по появившейся кнопке. Войдите и подтвердите доступ самостоятельно. После возврата Rezak показывает подтверждённые площадкой имя и ID аккаунта.
4. Повторите для остальных аккаунтов. В строке каждого стримера откройте **Аккаунты стримера**, выберите его YouTube и TikTok, сохраните каждую привязку.

### YouTube

В Google Cloud включите **YouTube Data API v3**, настройте OAuth consent screen и OAuth client для desktop-приложения. При тестовом статусе добавьте свою Google-учётную запись в тестовые пользователи. Используются `youtube.upload` и `youtube.readonly`: загрузка и проверка выбранного канала. При подключении выберите нужный YouTube-канал; для каждого канала нужен отдельный OAuth-сеанс.

Callback для обычного адреса студии: `http://127.0.0.1:8765/api/publishing/oauth/youtube/callback`. Точный адрес отображается в интерфейсе и зависит от используемого хоста/порта. Ограничения аккаунта, квоты и проверки Google сохраняются. Принятая загрузка не означает завершения обработки или гарантии открытого доступа.

### TikTok

В TikTok for Developers настройте **Login Kit for Desktop** и **Content Posting API**, получите доступ к `user.info.basic` и `video.upload`. Зарегистрируйте точный loopback callback: `http://127.0.0.1:8765/api/publishing/oauth/tiktok/callback` для стандартного адреса студии. Поддерживается PKCE согласно desktop-документации TikTok.

Используется **Upload / Inbox**, а не Direct Post. После передачи файла Rezak проверяет статус; после подтверждения TikTok нужно открыть уведомление в приложении и завершить публикацию. Название/описание не передаются этим endpoint: в очереди есть кнопка копирования текста. Разрешения приложения и доступность интеграции зависят от одобрения TikTok; обход ограничений не реализован.

## Отправка

- В **Готовых нарезках** нажмите **Отправить**. Для Twitch-ролика стример определяется по сохранённой связи с записью/задачей, а не по тексту названия. Если связи нет, интерфейс требует явно подтвердить стримера вручную.
- Выберите аккаунты назначения, проверьте название и описание. Для YouTube явно выберите доступ и отметку детского контента. Только кнопка подтверждения создаёт задания отправки.
- Авторство фонового видео автоматически добавляется в описание, если оно сохранено в метаданных ролика.
- Отдельная очередь показывает фактически переданные байты, состояние площадки, ошибки и ссылку YouTube. Она не занимает GPU-очередь монтажа. После подтверждения цель и параметры задания фиксируются.
- Отправка в аккаунт другого стримера отклоняется сервером. Перед передачей повторно проверяются принадлежность ролика, наличие аккаунта и текущая привязка. Смена привязки не перенаправляет старую задачу в новый аккаунт.
- Повторное добавление одной пары «файл + аккаунт» запрещено; используйте повтор существующей задачи. После обрыва передачи или перезапуска неопределённое задание требует проверки аккаунта. Повтор разрешается только после явного подтверждения, что ролика на площадке нет. Это уменьшает риск дублей; неизвестный результат нельзя автоматически считать неуспешной публикацией.

OAuth-токены и Client Secret защищены Windows DPAPI текущей учётной записи. Пароли площадок Rezak не получает. «Отключить локально» удаляет токены из Rezak; отзыв разрешения на стороне площадки выполняется в настройках самой площадки. Подключения, привязки и очередь хранятся в SQLite студии и переживают перезапуск.

## Проверка и ограничения

Протоколы OAuth, обновления токенов и загрузки проверяются HTTP-mocks; браузерные сценарии — на изолированных mock-каналах/аккаунтах. Реальная отправка требует пользовательских OAuth-приложений и авторизации. Успешные тесты не означают прохождения аудита площадок или проверки реального аккаунта.

YouTube передаётся порциями через resumable upload protocol. При перезапуске приложения с неопределённым результатом сессия не продолжается автоматически. TikTok передаётся порциями и после завершения опрашивается до подтверждения Inbox; лимиты запросов учитываются. Автоматической публичной публикации TikTok нет. Ролики не отправляются сами сразу после рендера: сначала нужен просмотр и подтверждение.
