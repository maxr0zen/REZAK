# Нейросети в Docker

`bonsai` и `asr` — отдельные GPU-контейнеры. Требуются Docker Desktop (Linux/WSL2) и NVIDIA GPU. Проверена RTX 5060 Ti 8151 MiB.

Установка: `./scripts/setup-ai.ps1`. Существующая Bonsai2 берётся из `C:/AI/Bonsai/models/Ternary-Bonsai-2-27B-PTQ1_0.gguf`. Другой путь задаётся параметрами `-ModelDirectory` и `-ModelFile`. Скрипт считает SHA-256 весов, записывает `.env`, собирает образы, копирует модель в Linux volume и загружает Whisper small. Исходные веса подключаются только для чтения; повторной загрузки Bonsai нет. Linux-копия весов дополнительно занимает около 6 ГБ и устраняет медленный mmap через файловый мост Windows/WSL. При копировании проверяется SHA-256, затем файл переименовывается атомарно.

- Bonsai: PrismML llama-server `prism-b10787-73bfe6c` с проверкой SHA-256, CUDA 12.8, контекст 4096. API: `http://127.0.0.1:18181/v1` (порт меняется через BONSAI_HOST_PORT). Для PTQ1_0 нужен fork PrismML.
- ASR: faster-whisper 1.2.1, Whisper small с закреплённой revision, int8_float16. Одноразовый контейнер освобождает CUDA-память после завершения.
- Совместимость: PyAV закреплён на 16.1.0 (в 19 удалён используемый faster-whisper аргумент metadata_errors); lock-файл рассчитан на Linux x86_64 / Python 3.12.
- app: CPU-планировщик и FFmpeg. worker пока заготовка, полноценной очереди нет.

Источники: [PrismML](https://github.com/PrismML-Eng/Bonsai-demo), [faster-whisper](https://github.com/SYSTRAN/faster-whisper).

## Запись → нарезки

Поместите MP4 с аудио в `data/sources/stream.mp4`:

```powershell
.\scripts\process-stream.ps1 -SourceId stream
```

Скрипт останавливает Bonsai, выполняет ASR, ждёт завершения ASR-контейнера, запускает Bonsai и получает решения, затем рендерит. В конце останавливает Bonsai. Параллельные запуски скрипта блокируются. Не запускайте оба GPU-сервиса вручную одновременно на 8 ГБ. Параметр `-NoRender` сохраняет планы без рендера.

RAM ограничена: Bonsai — 5 ГБ, ASR — 3 ГБ. Кеш состояний Bonsai ограничен `--cache-ram 256`, дополнительные снимки контекста отключены `--ctx-checkpoints 0`: стандартный кеш 8192 МиБ превышал лимит контейнера и приводил к OOM на длинной последовательности запросов. GPU-offload Bonsai подбирается автоматически под свободную VRAM; часть слоёв может работать на CPU. На загруженном хосте 16 ГБ холодный запуск будет медленнее. Ожидание готовности API ограничено 600 секундами. После обрыва клиент ждёт `/health` до 360 секунд и повторяет запрос один раз; Docker перезапускает упавшую модель до трёх раз. Сохранённые решения окон не зависят от внутреннего кеша сервера.

Экспорт: `data/exports`. Расшифровки и планы: volume `artifacts`, каталоги `/data/transcripts` и `/data/analysis`. ASR-модель: volume `asr-models`; Bonsai: volume `bonsai-models`. Исходники подключены только для чтения. Volumes переживают пересоздание контейнеров; не удаляйте их, если нужны результаты.

На каждый эпизод формируется вертикальный план, из общей библиотеки — горизонтальная подборка. Модель возвращает ID ASR-сегментов, причину и необходимость внешнего контекста. Код проверяет JSON и границы. Shell-команды от модели не исполняются. Две попытки валидации, затем ошибка с сохранением ответа. «Подходящих моментов недостаточно» — штатный результат.

Кеш учитывает исходник, ASR-конфигурацию, prompt и revision Bonsai/runtime. Изменение рендера не запускает ASR повторно. Пользовательские версии правок и полноценное восстановление задач пока отсутствуют.

Проверки: `docker compose --profile asr --profile llm config --quiet` и `.venv/Scripts/python.exe -m pytest -q`. Host-тесты рендера требуют `REZAK_INTEGRATION=1`, `FFMPEG` и `FFPROBE`; источник создаётся через `python -m scripts.smoke`. Для проверки распознавания подготовлен `data/sources/smoke-story.mp4` с синтетической речью Windows TTS.

## Ограничения

На тестовой англоязычной речи Windows TTS распознавание содержало ошибки, а объяснения Bonsai — фактические неточности. Технический сквозной тест подтверждает работу связки, но не качество автоматического отбора. Расшифровку, обоснования и готовые эпизоды пока нужно проверять вручную. Для сохранения подводки выбранные границы расширяются на соседний ASR-сегмент в пределах окна.

Качество выбора на реальных эфирах ещё нужно измерить. Превью: 360×640 или 640×360, 30 fps, H.264/AAC; padding сохраняет кадр. Webcam/two-zone, HDR, сложные PTS, длинные записи и production-размеры ещё не проверены. Vision-projector не загружен. UI, SQLite-очередь и Twitch отсутствуют. Перед публикацией MP4 проверяются метаданные и полное декодирование.
